API Documentation

List of available API endpoints and their functions

01
Server Status
GET
/api/status
Retrieves server status information in real-time. The response contains online, motd, level_name, id_seed, port, players, max_players, minecraft_version, protocol_version, and array player_names.
Response JSON 
{
  "online": true,
  "motd": "Endstone Server",
  "level_name": "Bedrock level",
  "id_seed": xxxxxxxxxxxxxxxxxxxx,
  "port": 19132,
  "players": 1,
  "max_players": 10,
  "minecraft_version": "1.26.52",
  "protocol_version": 2193,
  "player_names": ["STEVE"]
}
02
Player Details
GET
/api/list?player=<nama>
Retrieves the full details of a player. The player parameter is required. The data includes name, uuid, profile (skin_id & url avatar), status, health, max_health, coordinates (x, y, z, dimension), deaths, mob_kills, first_join, play_time, play_time_formatted, and last_played.
Response JSON 
{
  "name": "STEVE",
  "uuid": "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxx",
  "profile": {
    "skin_id": "persona-xxxxxxxxxxxxxxxx-x",
    "url": "/api/avatar?player=STEVE"
  },
  "status": "online",
  "health": 20,
  "max_health": 20,
  "coordinates": {
    "x": 123.5,
    "y": 71.0625,
    "z": 36.5,
    "dimension": "Overworld"
  },
  "deaths": 0,
  "mob_kills": 0,
  "first_join": "2026-10-10T10:42:09Z",
  "play_time": 68,
  "play_time_formatted": "1m 8s",
  "last_played": "2026-10-10T10:42:09Z"
}
03
Chat Message
GET
/api/massege
/api/massege?limit=100
/api/massege?after_id=500&limit=500
Retrieves a list of chat messages from the server. Optional parameters: limit (number of messages) and after_id (retrieve messages after a specific ID). The response contains count, last_id, has_more, dan array messages where each item contains id, name, timestamp, profile_url, dimension, and message.
Response JSON 
{
  "count": 1,
  "last_id": 1,
  "has_more": false,
  "messages": [
    {
      "id": 1,
      "name": "STEVE",
      "timestamp": "2026-10-10 12:22:12",
      "profile_url": "/api/avatar?player=STEVE",
      "dimension": "Overworld",
      "message": "hello stone"
    }
  ]
}
04
Player Avatar
GET
/api/avatar?player=<nama>
Retrieves a player's avatar (profile photo) in PNG format. The player parameter is required and must specify the player's name. This endpoint is used by the Status and Message pages to display the player's profile icon. The image is square (1:1 aspect ratio) and is cacheable by browsers.
Response Image
Response: Binary image (image/png)
Size: 1:1 (square)
Content-Type: image/png
GET /api/avatar?player=<nama>

Flexibility in File and Folder Structure

Guide to organizing website project files and folders

Users and developers are given complete freedom to create, organize, and manage files and subfolders according to their project needs, without having to follow the default directory structure defined by the system. Developers are not limited to just a few specific files or folders, but can create as many HTML, CSS, JavaScript, and other supporting files as needed.

Developers can also group files based on their functions and purposes to make the project structure neater, more organized, and easier to develop. For example, developers can create several HTML pages for different features, such as the Home, Status, Message, and Document pages. Each page can use its own CSS and JavaScript files, so the code for each feature can be managed separately without having to combine all the code into a single file.

Example of a Folder Structure

Here is an example of a folder structure you can use:

Folder Structure 
website/
├── index.html              # Required homepage
├── home.html               # Home page
├── status.html             # Status page
├── message.html            # Message page
├── document.html           # Document page
│
├── css/
│   ├── style.css           # CSS Mian
│   ├── home.css            # CSS Home page
│   ├── status.css          # CSS Status page
│   ├── message.css         # CSS Message page
│   └── document.css        # CSS Document page
│
├── js/
│   ├── script.js           # JavaScript main
│   ├── home.js             # JavaScript Home page
│   ├── status.js           # JavaScript Status page
│   ├── message.js          # JavaScript Message page
│   └── document.js         # JavaScript Document page
│
├── assets/
│   ├── images/             # Images and icons
│   ├── fonts/              # Font file
│   └── icons/              # Additional icons
│
└── pages/
    ├── settings.html       # Additional Settings Page
    └── profile.html        # Additional profile page

The structure above is merely an example and is not a required directory structure. Developers are free to rename folders, add subfolders, move files, or create other structures as needed for the project. For example, CSS and JavaScript files can be placed in the same folder as the HTML files, or each page can have its own folder containing HTML, CSS, and JavaScript files.

The index.html file is required

Although the file and folder structure can be organized freely, the index.html file remains mandatory and cannot be replaced as the main file. The system uses this file as the entry point when users access the main website page. Therefore, the index.html file must remain in the website’s root directory and must not be deleted or renamed.
